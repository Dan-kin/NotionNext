# 自动发布标准（四周受控试点）

## 发布边界

自动发布仅适用于「本周去看」的事实型短讯。内容只能包含经过主办方页面确认的展览名称、场馆、开始和结束日期、原始链接，以及清楚标注来源的简短中文说明。没有图片使用许可时，不抓取、转载或热链来源图片；站点可使用自有通用视觉。机器评分只决定人工候选的排序，不授予发布资格。

「机会雷达」「艺术路径」「中法连接」继续人工核验：申请资格、费用、版权、跨国适用性或解释性判断无法只凭通用页面元数据安全确定。

## 一票否决门槛

1. 来源必须是白名单内主办方或场馆的一手官网；Offi、Slash Paris、On the Move 等发现渠道只进入人工候选。
2. 列表标题与详情页标题必须指向同一活动，详情页成功读取，规范化 URL 必须属于该一手来源。
3. 详情页必须提供结构化的活动开始、结束日期和场馆；正文中猜测的日期、缺失场馆、结束日期或疑似取消均暂停。
4. 活动结束日期尚未过去，开始日期距离采集日不超过前后 14 天；过期与过远活动暂停。
5. 与 Notion **全部状态**（Published、Draft、Invisible）中的原始来源 URL、已知外部 URL、规范化标题及主题别名比对；任何疑似重复暂停。现有网站 archive 只是补充检查，不可代替 Notion 全量查重。
6. 自动任务必须能读到完整 Notion URL 索引、确认目标数据库/schema/写权限，并能在同一轮写入后回读核对。任一检查失败则整轮不发布。
7. 仅 2026 年 10 月四个指定周一、每自然周最多发布 1 条，且只新建标准化短讯；不改动现有文章或任何已有 `status`。每条写入前再查一次来源 URL，避免重试造成重复。
8. 发布时保留原始链接和采集时间；不声称已核实票价、预约条件或图片权利，除非一手页面有明确字段。发布时间和活动时间分别呈现。
9. 发布后验证文章 URL、首页与展览活动栏目均出现；失败时停止后续发布并提醒 Dan，不自动修改已有文章。

## 当前实施状态

`yarn nd:content:screen` 使用确定性规则生成阻断原因，不调用 Notion 写入。Notion 数据库现有 `source_url` 属性，但旧稿尚未全部回填。筛选器须收到当天从 Notion 全状态、完整分页查询生成的私密 JSON 索引；没有索引时 `duplicate_check_unavailable` 会阻止所有自动发布。索引须包含 `databaseId`、`complete: true`、`queriedAt`、三个 `statusesQueried`、`totalPages` 和逐页的 `id`、`title`、`status`、`source_url`。索引文件仅存本地忽略目录，不进 GitHub。

示例：`node scripts/nd-content/screen-auto-publication.mjs <候选报告.json> <筛选结果.json> <Notion全量索引.json>`。索引不完整、超过 24 小时、页数低于已核对的 80 页，或标题/来源 URL 格式异常时，脚本拒绝继续。旧稿缺失 `source_url` 仍须使用标题、日期和正文中的原始链接人工复核，不能把空值视作不存在重复。

任务级试点已设置，但端到端自动发布器尚未完成。这意味着每周任务只有在确定性筛选确实通过、全库重复复核和 Draft 回读验证后才可写入 Published；当前 GitHub `main` 尚未包含本文件与筛选器，故下一次运行应安全地只报告，不得声称自动发布成功。

扩大试点前，需要完成三项实施：

1. 将当前分支通过 PR 合并到 GitHub `main`，并回填或索引既有 Published、Draft、Invisible 页面中的来源链接，确保跨语言旧稿也能查重。
2. 实现「新建短讯 → 回读验证 → 检查站点首页/栏目」的幂等发布器，并在测试数据库或隔离页面验证失败与重试行为。
3. 先运行一轮只读影子筛选，确认无错配、误分类和重复；再把私密每周任务接入经过测试的发布器。

临时放宽分数、跳过查重或直接让模型把候选改为 Published 不符合此标准。四周后仅继续私密候选报告，扩大范围须重新授权。
